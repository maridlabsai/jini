# Marketing Site Uplift

Updated: 2026-05-17

## Purpose

Align the Jini site with current high-performing AI product marketing patterns
 without turning it into a generic AI-builder landing page.

## Observed Modern Patterns

Across current AI tool and framework sites, the common winning patterns are:

1. One sharp promise above the fold.
2. One primary CTA, not a configuration matrix.
3. Proof of value within the first scroll.
4. Compatibility and ecosystem trust shown early, but after the main promise.
5. Clear “how it works” steps in plain language.
6. Product-first wording instead of internal runtime vocabulary.
7. Visual proof or motion before deep documentation.

Representative references:

- [Claude Code](https://claude.com/product/claude-code)
- [Cursor](https://cursor.com/)
- [Kiro](https://kiro.dev/)
- [GitHub Copilot](https://github.com/features/copilot)

## Jini Translation

Jini should not market itself as:

- another model switcher
- another “build anything” AI builder
- a provider setup shell

Jini should market itself as:

- the calm front door for messy work
- a way to get to handoff-ready output faster
- a system that keeps status, missing pieces, and next steps visible
- a product that defaults to the cheapest suitable route while keeping control visible

## Site Decisions

1. Homepage is outcome-first, not provider-first.
2. Primary CTA is install, not route selection.
3. Provider compatibility is shown as support proof, not the main decision surface.
4. Proof appears as:
   - practical fact strip
   - animated examples
   - concrete use-case cards
5. The marketing homepage does not carry orientation chrome that belongs on docs pages.
6. Shared shell language should be:
   - plain
   - low-jargon
   - still explicit where trust matters

## Success Criteria

The site uplift passes when:

- a new visitor can explain Jini in one sentence after the first screen
- the first CTA is obvious
- the homepage does not force provider thinking too early
- the site shows proof before dense explanation
- the install path still converges to `jini`

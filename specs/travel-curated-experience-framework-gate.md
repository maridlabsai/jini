# Travel Curated Experience Framework Gate

Updated: 2026-05-19

## Purpose

This gate determines whether the public travel experience framework is strong
enough to guide work without collapsing into generic itinerary behavior or
unsupported execution claims.

## Gate Categories

### 1. Scoped Intake Quality

The framework must require:

- targeted clarification for underspecified requests
- missing-dimension logic instead of one fixed travel questionnaire

### 2. Curation Quality

The framework must require:

- curated option sets
- itinerary plus decision support
- budget, logistics, and still-to-confirm visibility

### 3. Continuity Quality

The framework must define:

- what survives across CLI, desktop, and mobile
- one trip thread model instead of separate surface-specific states

### 4. Trust And Execution Boundaries

The framework must make:

- planning versus execution boundaries explicit
- confirmation-first execution a non-negotiable rule

### 5. Competitive Realism

The framework must:

- learn from Layla and Navan Edge
- avoid implying live-booking parity where none exists yet

## Pass Conditions

The framework passes only if:

- all categories above are addressed directly
- the commercial relationship is explicit
- the shipping-now versus later split is explicit
- the framework rejects destination-specific hardcoding and generic itinerary
  behavior

## Reject Conditions

Reject if any are true:

- the document allows generic itinerary-first behavior
- the document confuses planning with booking
- the document implies live execution capabilities as current public truth
- the document does not define what continuity means for travel work
